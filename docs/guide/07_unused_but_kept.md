# 07. 使っていないが残しているもの

旧系統（SecurityReport系）のコードは、2026-08-02の新系統切り替え後にすべて削除済み（何をいつ消したかはgit履歴が持つ）。最後まで凍結保管していた `security_reports` テーブルも、新系統のデータ品質確認を終えたため2026-09-01にバックアップの上削除した（記録は次節）。現在、**どこからも参照されていないが意図的に残しているもの**は無い。この文書は、削除済みデータの復元手段の記録と、「参照ゼロ」に見えても削除してはいけないものの一覧。

## 削除済み: `security_reports`（旧系統の凍結データ）

旧系統が取り込んでいた横持ちテーブル（1有報 = 1行で、連結・単体 * 約30科目を横並びのカラムで持つ。新系統の縦持ち `financial_statement_items` と対照的。[03章](03_data_flow.md)）。旧cron停止に伴い2026-08-02の内容で凍結し、新系統の取込結果との突き合わせ検証に使っていた。

| 観点 | 内容 |
|---|---|
| 削除日 | 2026-09-01（`db/migrate/20260901000001_drop_security_reports.rb`） |
| バックアップ | 本番VPSの `~/backups/security_reports_20260901.sql.gz` と、ローカルPCの `~/Downloads/security_reports_20260901.sql.gz`（pg_dumpのプレーンSQL形式をgzip圧縮） |
| 復元方法 | `gunzip -c security_reports_20260901.sql.gz \| psql <本番と同じ接続先>`（テーブル定義・データ・インデックス・外部キーごと復元される。外部キー参照先の `companies` が先に存在していること） |
| マイグレーション | create（`20230904131246`）とdropの両ファイルを履歴として残す（消すとマイグレーション履歴の整合が壊れる） |

## 旧系統の名残に見えるが、違うもの

削除候補に挙げる前にここを確認する。

| 見えるもの | 実態 |
|---|---|
| `companies` テーブル | 旧系統時代からあるテーブルだが、新系統（`Disclosure::Company`）が使用中。**削除・変更禁止** |
| `Gemfile.lock` の `rexml` | 旧XMLパーサの名残ではなく、他gemの推移的依存。`Gemfile` 直下の依存としては削除済み |
| backendの `.gitignore` / `exclude_from.txt` の `security_reports` 行 | 削除したDBテーブルの名残ではなく、XBRL調査時に有報zipを展開するローカル作業ディレクトリ `application/backend/security_reports/` の除外指定。消すと作業ディレクトリが未追跡ファイル・rsync対象になってしまう |
