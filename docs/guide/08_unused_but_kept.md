# 08. 使っていないが残しているもの

旧系統（SecurityReport系）のコードは、2026-08-02の新系統切り替え後にすべて削除済みで、現在のコードベースに旧系統の実装は存在しない（何をいつ消したかはgit履歴が持つ）。この文書は、**どこからも参照されていないが意図的に残しているもの**の一覧と、消してよくなる条件の記録。「参照ゼロ」だけを理由に削除しないための文書でもある。

## 一覧

| 残しているもの | 場所 | 残す理由 |
|---|---|---|
| `security_reports` テーブルと凍結データ | 本番PostgreSQL | 旧系統の取込結果との突き合わせ用（次節） |
| `security_reports` のテーブル定義 | backendの `db/schema.rb`・`db/migrate/20230904131246_create_financial_statement_documents.rb` | 定義だけ消すと本番の実テーブルと `schema.rb` が食い違い、マイグレーション履歴の整合も壊れる。テーブル本体の扱いが決まるまで触らない |
| テスト実行基盤（CRA雛形） | frontendの `src/setupTests.ts` と `craco test` | テストコードは0件（[05章](05_frontend.md)）だが、書き始めるときの土台としてそのまま残す |

## `security_reports`: 旧系統の凍結データ

| 観点 | 内容 |
|---|---|
| 何か | 旧系統が取り込んでいた横持ちテーブル。1有報 = 1行で、連結・単体 × 約30科目を横並びのカラムで持つ（新系統の縦持ち `financial_statement_items` と対照的。[03章](03_system_overview.md)） |
| 状態 | 旧cron停止に伴い**2026-08-02時点の内容で凍結**。以後、書き込みも読み取りもない（コードからの参照はゼロ） |
| 残す理由 | 新系統の取込結果を検証するときに突き合わせられる実データ。旧系統が横持ちゆえに抱えていた不具合（IFRS企業の全カラムが0で保存される等）の証跡でもある |
| ローカル・新規環境 | `db:schema:load` により**空の同名テーブルだけ**が作られる。凍結データがあるのは本番のみ |

### 消してよくなる条件と手順

- 参照ゼロは削除の理由にしない。このテーブルの価値は「照合できること」で、コードから参照されないのは前提
- 新系統のデータ品質が確認でき、旧データとの突き合わせがもう不要と判断できたら消してよい
- 消すときは `pg_dump` でバックアップ → `drop_table` のマイグレーション → `schema.rb` 再生成の順。旧マイグレーションファイルは履歴として消さない
- それまでは**何もしない**（`drop_table` のマイグレーションを先回りで作らない）

## 紛らわしいが「残置物」ではないもの

旧系統の名残に見えるが、実態が異なるもの。削除候補に挙げる前にここを確認する。

| 見えるもの | 実態 |
|---|---|
| `companies` テーブル | 旧系統時代からあるテーブルだが、新系統（`Disclosure::Company`）が使用中。**削除・変更禁止** |
| `Gemfile.lock` の `rexml` | 旧XMLパーサの名残ではなく、他gemの推移的依存。`Gemfile` 直下の依存としては削除済み |
